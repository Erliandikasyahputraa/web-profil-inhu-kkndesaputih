# The Quality Gate

### Project Identity
This project is not a website.
It is an interactive documentary about Desa Air Putih.
Every engineering decision exists to strengthen that experience.

---

This Quality Gate governs the entire project.
Every page.
Every scene.
Every viewport.
Without exception.

## The Rules of Survival

### 1. Guilty Until Proven Beautiful
Every scene is guilty until proven beautiful. No scene is protected. No scene is considered finished because it already exists. Evaluate every scene from zero. Keep only what deserves to survive.

### 2. The Frame Test
Before committing any layout, ask only one question:
**Would someone save a screenshot of this frame on Pinterest or Behance?**
If the answer is no, keep iterating.

### 3. The Three Second Test
A visitor should understand the emotional purpose of a frame within three seconds.
Not the information. The emotion.
If the emotional intention is unclear, the frame must be redesigned.

### 4. Merging and Compressing
Scene count is not a success metric.
If three scenes can become one stronger scene, merge them.
If one scene feels stretched, compress it.
The documentary should feel inevitable, never repetitive.

### 5. The Single Question Rule
Every scene must answer only one question.
If a scene tries to communicate multiple ideas, split it.
If multiple scenes communicate the same idea, merge them.

### 6. Emotional Progression
Never repeat the same emotional message twice.
If the previous image already says "peace", the next image must say "life", "history", "community", or "hope". Emotion must progress, not repeat.

### 7. The Stopping Rule
If I stop scrolling at any moment, I should immediately know why this frame exists.
If the purpose of a frame is unclear, delete it.

### 8. The Navigation
The navigation should feel like the opening chapter list of a documentary.
Not an application menu.
Not a dashboard.
Not a website sitemap.
The visitor should immediately understand the entire journey before scrolling.

## The Paradigm Shift

### No Emotional Attachment
Do not defend existing layouts.
Do not preserve scenes because they took time to build.
Delete without regret.
Only the final experience matters.

### Forget Components
Never evaluate: Hero, Timeline, Gallery, CTA, Navbar.
Evaluate only: Frames, Moments, Transitions, Rhythm, Emotion.

### Transition Audit
The transition between scenes is as important as the scenes themselves.
If one frame ends abruptly, or the next frame feels disconnected, recompose both.
Transitions should feel inevitable, not assembled.

### Reject Safe Design
Average layouts are failures.
Safe solutions are failures.
Predictable compositions are failures.
If a frame looks like something found in a random Figma community file, start over.

### Kill the Template
If a layout resembles a landing page, portfolio, agency website, government portal, or SaaS product, it has failed.
This documentary must feel unmistakably unique.
Someone should recognize the project after seeing only one screenshot.

### Eliminate the AI Look
Avoid layouts that feel AI-generated.
Avoid perfect spacing everywhere.
Avoid mechanical alternation.
Avoid formulaic left-right-left-right compositions.
The experience must feel art-directed by a human.

### Break Predictability
Perfect symmetry is suspicious.
Perfect repetition is boring.
Every few scrolls, change the rhythm, change the scale, change the balance.
Keep the visitor curious.

### Components are Disposable
If achieving a better frame requires deleting an entire component, delete it.
The component tree exists to serve the documentary. Never the opposite.

### Human Review
Do not perform automated screenshot analysis.
Do not create visual reports.
Do not open browsers unless explicitly instructed.
Implement the requested scene only.
The human reviewer is responsible for judging the visual quality and providing feedback.
Wait for approval before continuing to the next scene.

### Incremental Execution
Never continue to the next page automatically.
Never redesign multiple pages in one iteration.
Complete one scene.
Stop.
Wait for review.
Apply feedback.
Only then continue.

### No Autonomous Decisions
Do not expand the scope.
Do not redesign unrelated pages.
Do not refactor untouched code.
Do only what was requested.
Stop immediately after completing the assigned scene.

### Mobile First Emotion
Most visitors will experience this documentary on mobile.
Never treat mobile as a responsive adaptation.
Design mobile as the primary cinematic experience.
Desktop is the expansion, not the default.

---

Nothing is sacred.
Everything is replaceable.
Only the experience survives.
